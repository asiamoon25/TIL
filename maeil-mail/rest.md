# REST 란

### REST 란

REST(Representational State Transfer) 는 웹 상에서 분산 시스템, 특히 클라이언트와 서버 간의 상호 작용을 설계하기 위한 아키텍처 스타일임.

2000년 로이 필딩이 자신의 박사학위 논문에서 처음 소개한 개념으로, 오늘날 RESTful API 를 통해 웹 애플리케이션이 데이터를 주고받는 표준 방식 중 하나로 자리 잡았음.

***

### 핵심 개념

#### Resource

* 정의 : REST 에서는 모든 것이 리소스(데이터나 기능)로 취급됨. 예를 들어, 사용자, 게시글, 사진 등이 모두 리소스임.
* 식별 : 각 리소스는 고유한 URI(Uniform Resource Identifier) 를 통해 식별됨. 예를 들어, `https://api.example.com/users/123` 는 ID 가 123인 사용자를 나타냄.

#### 표현(Representation)

* 정의 : 클라이언트와 서버는 리소스의 상태를 전송할 때 그 리소스의 '표현'(Representation) 을 주고받음. 일반적으로 JSON, XML, HTML 등 다양한 형식으로 표현됨.
* 역할 : 클라이언트는 서버가 보낸 표현을 해석하여 화면에 표시하거나, 추가적인 처리를 할 수 있음.

#### HTTP 메서드

* GET : 리소스 조회
* POST : 리소스 생성
* PUT/PATCH : 리소스 수정(전체 또는 일부)
* DELETE : 리소스 삭제

### REST 의 제약 조건

REST 아키텍처는 몇 가지 중요한 제약 조건을 따름. 이 제약 조건들을 지킴으로써 시스템은 확장성과 성능, 독립성을 확보할 수 있음.

#### 클라이언트-서버 구조

* 설명 : 클라이언트(사용자 인터페이스)와 서버(데이터 및 비즈니스 로직) 가 분리되어 서로 독립적으로 발전할 수 있음.
* 장점 : 서로 다른 기술 스택을 사용이 가능하며, 보안, 확장성, 유지보수가 용이해짐.

#### Stateless(무상태성)

* 설명 : 각 요청은 서버가 이전의 요청 상태를 저장하지 않는 독립적인 단위로 처리됨. 모든 필요한 정보는 요청 안에 포함되어야 함.
* 장점 : 서버의 복잡성을 줄이고, 확장성을 높이며, 요청이 독립적이므로 부하 분산이 용이함.

#### 캐시 처리 가능(Cacheable)

* 설명 : HTTP 프로토콜의 캐시 메커니즘을 활용하여, 클라이언트나 중간 프록시가 응답을 저장해 두고 동일한 요청에 대해 서버의 부하를 줄일 수 있음.
* 장점 : 응답 속도가 빨라지고, 네트워크 트래픽이 줄어듬.

#### 계층화된 시스템(Layered System)

* 설명 : 클라이언트는 보통 서버에 직접 접근하는 것이 아니라 여러 중간 계층(예 : 로드 밸런서, 프록시, 게이트웨이 등) 을 통해 서버와 통신함.
* 장점 : 보안, 로드 분산, 그리고 시스템 구조의 유연성이 향상됨.

#### 균일한 인터페이스(Uniform Interface)

* 설명 : REST 는 클라이언트와 서버 간의 상호작용을 단순화하기 위해 일관된 인터페이스를 사용함. 이를 통해 서로 다른 시스템 간의 상호 운용성이 증대됨.
* 주요 원칙 :&#x20;
  * 리소스 식별 : URI 를 통한 명확한 식별
  * 표현의 전송 : 데이터는 다양한 포맷(JSON, XML 등) 으로 전송
  * 자체 서술적 메시지 : 메시지 자체에 충분한 정보가 포함되어 있어야 함.
  * 하이퍼미디어의 사용(HATEOAS) : 응답에 포함된 링크를 통해 클라이언트가 다음 행동을 결정할 수 있도록 지원

#### 코드 온 디맨드(선택적)

* 설명 : 서버가 클라이언트에게 실행 가능한 코드를 전송할 수 있는 옵션임. 예를 들어 JavaScript 코드를 클라이언트에게 보내 실행하게 할 수 있음.
* 주의 : 이 제약 조건은 선택적이며, 모든 RESTful  시스템에 사용되지는 않음.

### RESTful API

REST 의 원칙을 따르는 웹 API 를 흔히 **RESTful API** 라고 부름. RESTful API 는 다음과 같은 특징을 가짐.

* 자원의 명확한 표현 : 각 리소스는 URI 를 통해 식별되고, HTTP 메서드를 통해 조작됨.
* 무상태성 : 각 요청은 독립적이며 필요한 모든 정보를 포함함.
* 표준화된 응답 : 응답은 주로 JSON 또는 XML 포맷으로 제공되어, 다양한 클라이언트에서 쉽게 파싱할 수 있음.
* 확장성 및 유지보수 용이 : 클라이언트와 서버의 분리가 명확하여, 시스템 확장이 용이하고 유지 보수가 편리함.

***

### REST 의 장단점

#### 장점

* 단순성 : HTTP 프로토콜의 표준 메서드와 URI 를 사용하여 이해하기 쉬움.
* 유연성 : 다양한 클라이언트(웹, 모바일 등)와 쉽게 통신할 수 있음.
* 확장성 : 무상태성과 계층화된 아키텍처 덕분에 서버 확장이 용이함.
* 캐싱 : HTTP 캐시를 활용해 응답 속도를 높이고 서버 부하를 줄일 수 있음.

#### 단점

* 복잡한 트랜잭션 처리의 어려움 : 상태를 서버에 저장하지 않기 때문에, 여러 요청 간의 트랜잭션 관리가 어려울 수 있음.
* HATEOAS 구현의 어려움 : 완전한 하이퍼미디어 제어를 구현하기가 현실적으로 복잡할 수 있음.
* HTTP 의존성 : REST 는 주로 HTTP 프로토콜에 기반하므로, 다른 프로토콜에서는 적용이 어려울 수 있음.
