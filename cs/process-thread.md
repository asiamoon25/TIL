# Process 와 Thread

## Process

✅ **프로세스란?**

* 실행 중인 프로그램의 인스턴스를 의미함.
* 운영체제에서 하나의 독립적인 작업 단위로 관리됨.
* 각 프로세스는 **독립적인 메모리 공간** (코드, 데이터, 힙, 스택) 을 가짐.
* CPU  스케줄링을 받아 실행됨.

✅ **프로세스의 특징**

1. 독립된 실행 환경
   1. 다른 프로세스와 메모리를 공유하지 않음.
   2. 한 프로세스가 다른 프로세스의 메모리에 접근할 수 없음.
2. 멀티 프로세스 지원
   1. 하나의 프로그램이 여러 개의 프로세서로 실행될 수 있음.
   2. 각 프로세스는 독립적으로 동작하며, 별도의 메모리 공간을 사용함.
3. 컨텍스트 스위칭 필요
   1. 프로세스 간 전환 시 OS 가 현재 실행 중인 프로세스 상태를 저장하고, 새로운 프로세스의 상태를 복원하는 과정이 필요함.
   2. 컨텍스트 스위칭 비용이 크기 때문에 프로세스 간 전환은 비교적 느림.
4. IPC(Inter-Process Communication, 프로세스 간 통신) 필요
   1. 프로세스는 서로 독립적이므로 데이터를 공유하려면, **파이프, 메시지, 큐, 공유 메모리, 소켓** 같은 방법이 필요함.

## Thread

✅ **쓰레드란?**

* 프로세스 내에서 실행되는 가장 작은 단위
* 하나의 프로세스는 여러 개의 쓰레드를 가질 수 있음.
* **같은 프로세스의 메모리 공간(코드, 데이터, 힙) 을 공유** 하지만, 각 쓰레드는 독립적인 스택과 레지스터를 가짐.

✅**쓰레드의 특징**

1. 경량(Lightweight) 프로세스

* 프로세스보다 적은 자원을 사용함.
* 프로세스를 생성하는 것보다 쓰레드를 생성하는 것이 비용이 적음.

2. 메모리 공유

* 같은 프로세스 내의 쓰레드는 동일한 힙과 데이터 영역을 공유함.
* 따라서 쓰레드 간 데이터 공유가 쉬움.
* 하지만, 동기화 이슈(레이스 컨디션, 데드락 등) 가 발생할 수 있음.

3. 빠른 컨텍스트 스위칭

* 쓰레드는 같은 프로세스 내에서 실행되므로 프로세스 간 전환보다 빠르게 실행 가능.

4. 멀티쓰레딩 지원

* 하나의 프로세스에서 여러 개의 쓰레드를 동시에 실행하여 멀티태스킹을 가능하게 함.
* 다만, **멀티 쓰레딩 환경에서는 동기화 문제가 발생할 가능성이 높음** -> **Mutex(뮤텍스), Semaphore(세마포어), Lock** 등을 이용한 동기화가 필요함.
